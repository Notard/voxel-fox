결과 보고서 — 복셀 여우 타일 게임

작성일: 2026-09-29 · 웹 보고서: notard.github.io/voxel-fox · 저장소: github.com/Notard/voxel-fox · 상세 기록: WORKLOG.md · 계획서: plan.md · 체크리스트: TODO.md

1. 요약

복셀 스타일 흰 여우가 구멍 2개가 뚫린 4×4 타일맵을 돌아다니며 코인 4개를 모으는 짧은 3D 게임을 계획서대로 끝까지 만들었다.

항목 결과
완성도 체크리스트 81 / 81 완료. 계획서 1~8단계 전부와 사용자 피드백으로 추가한 5개 하위 단계
결과물 Windows 실행 파일 VoxelFox/Build/VoxelFox.exe (102.7MB, 빌드 경고·에러 0). 사용자가 처음부터 끝까지 직접 플레이해 확인
자동 테스트 EditMode 27개, PlayMode 35개 모두 통과
코드 게임 스크립트 7개(591줄), 에디터 자동화·테스트 포함 C# 약 3,200줄. Blender Python 스크립트 2개
기간 2026-09-29 하루 (첫 커밋 11:31 → 마지막 커밋 16:01), 커밋 18개
환경 Unity 6000.5.7f1 (URP), Blender 5.2, Windows 11

2. 게임 구성

요소 내용
캐릭터 흰 복셀 여우 (복셀 612개, 코~꼬리 1.24m). Idle / Walk / Jump 동작
맵 4×4 타일(한 칸 2m), 구멍 2개, 둘레는 낭떠러지. 잔디 블록에 노멀맵으로 입체감
조작 WASD·방향키(게임패드) 이동, Space 점프, R 재시작. 화살표는 타일 격자 방향으로 곧게 움직인다
카메라 여우를 화면 가운데에 두고 따라가는 쿼터뷰 (45°, 방향 30°, 거리 11m)
아이템 복셀 코인 4개. 돌면서 둥실거리고, 닿으면 금색 반짝이와 함께 사라진다. 좌상단 아이템 n / 4
결과 떨어지면(y < -5) GAME OVER, 코인 4개를 모두 모으면 CLEAR!(걸린 시간 표시). 결과가 나오면 조작·시간 정지
재시작 R 키(언제든) 또는 결과 패널의 [다시 하기] 버튼 → 모든 것이 처음 상태로
여우 코인 아이콘
GAME OVER CLEAR!

3. 단계별 결과

단계 내용 검증
1. Unity 프로젝트 Universal 3D 템플릿, Input System, TextMeshPro, Main 씬, 템플릿 샘플 정리, GitHub 공개 저장소(LFS) PlayMode 스모크 테스트
2. 여우 캐릭터 Blender Python 스크립트 하나로 복셀 모델 → 리그(본 8개, 강체 스키닝) → 동작 3개 → FBX. Unity 임포트·Animator 자동 설정 EditMode 9개
2-1. 흰 여우 · 0.9배 사용자 요청으로 붉은 여우 → 흰 여우, 크기 0.9배 재생성 후 테스트 통과
3. 타일맵 + 이동 문자열 레이아웃 → 타일·구멍·시작점, CharacterController 이동·점프, 쿼터뷰 카메라 걷기·점프·구멍/가장자리 낙하
3-1. 바닥 노멀맵 사용자 요청. 팔레트 → 색·노멀 아틀라스, 잔디 덩어리 턱 + 둥근 타일 모서리 노멀맵·접선 테스트
4. 애니메이션 연결 Speed / IsGrounded / Jump, Walk 배속을 이동 속도에 맞춤 발 미끄러짐 최대 1.3cm
4-1. 카메라 · 이동 방향 사용자 피드백. 여우를 따라가는 카메라, 화살표를 격자 방향으로 북쪽 직진 시 옆 이동 0m
4-2. 카메라 거리 (되돌림) 1.5배로 늘렸다가, 원인이 Game 창 Scale 5배로 밝혀져 되돌림 —
4-3. 점프 거리 사용자 피드백. 2.08m → 2.68m (구멍 2m) 가장자리 0.4m 앞에서 뛰어도 구멍을 넘음
5. 아이템 복셀 코인, 획득·반짝이, 한글 카운터 획득·카운트·전부 모으기
6. 게임 종료 / 성공 GAME OVER / CLEAR! 패널, 조작·시간 정지 두 결과, CLEAR 뒤 낙하에도 유지
7. 재시작 씬 다시 불러오기, R 키·버튼 가상 키보드 R, 두 번 재시작 후 중복 집계 없음
8. 마무리 Windows 빌드, Codex로 그린 아이콘 실행 로그 에러 없음, 사용자 플레이 확인

4. 사용자 피드백으로 바뀐 것

플레이해 본 사용자의 의견을 받아 하위 단계로 고치고, 이유를 모두 기록했다.

요청 원인 조치
"더 예쁜 여우로" — 흰 여우 3톤 털, 분홍 귀 안쪽, 크림색 볼, 0.9배 (2-1)
바닥 입체감 색 무늬만 있어 평평해 보임 노멀맵 아틀라스 (3-1)
카메라가 캐릭터를 따라가야 함 맵 전체를 비추는 고정 카메라 여우를 가운데 두고 따라가는 카메라 (4-1)
화살표를 누르면 대각선으로 감 카메라가 격자에서 30° 돌아가 있는데 입력은 화면 기준 입력을 가장 가까운 격자 축으로 (4-1)
카메라를 멀리, 여우를 가운데로 실제 원인은 Game 창 Scale 5배 변경 후 되돌림, 이력은 남김 (4-2)
점프가 짧아 구멍에 잘 빠짐 달리며 뛴 거리 2.08m ≈ 구멍 너비 2m 높이 1.5m, 중력 -15 → 2.68m (4-3)

5. 주요 설계 결정

  • 모든 에셋을 스크립트로 만든다. 여우는 Blender/make_fox.py, 타일·코인·UI·씬 배치는 에디터 스크립트(SceneBuild = 맵 → 아이템 → UI)가 만든다. 값 하나를 바꾸고 다시 실행하면 결과가 똑같이 재현된다.
  • 발 미끄러짐을 계산으로 맞춘다. Walk 클립에서 발끝 보폭을 재서 "1배속일 때 맞는 이동 속도(0.868 m/s)"를 구하고, 게임 중 실제 속도 ÷ 이 값으로 재생 배속을 정한다. 보폭을 늘리려고 다리 각도를 26° → 40°로 바꿨다.
  • 타일은 실행할 때 만든다. 레이아웃 문자열만 고치면 맵이 바뀐다. 에디터에서는 기즈모로 배치를 보여 준다.
  • 한글 글꼴은 설치된 맑은 고딕을 실행 중에 불러온다. 맑은 고딕은 재배포할 수 없어 공개 저장소에 넣지 않았다. Windows 전용 게임이라 항상 설치되어 있다.
  • 재시작은 씬 다시 불러오기. 정적 이벤트는 OnDisable에서 반드시 떼어 재시작 뒤에도 코인을 두 번 세지 않는다.
  • 미리보기는 Play 모드에서 찍는다. 편집 모드에서는 스키닝이 갱신되지 않아 여우가 잘못 그려졌다. 단계마다 fox_preview.html, map_preview.html로 결과를 눈으로 확인했다.

6. 품질 검증

  • 자동 테스트 62개 (EditMode 27 · PlayMode 35). 모든 단계를 만들 때마다 전체를 다시 돌렸다.
  • 에셋: 여우 본·클립·크기, 타일·코인 크기와 콜라이더, 노멀맵 설정, 씬 연결
  • 동작: 이동 속도, 점프 높이·거리, 구멍·가장자리 낙하, 격자 방향 입력, 카메라 중앙 유지
  • 애니메이션: Idle / Walk / Jump 전환, 발 미끄러짐 측정(240fps)
  • 게임 흐름: 코인 획득, GAME OVER / CLEAR, 조작·시간 정지, 재시작(가상 키보드 R 입력 포함)
  • 테스트는 Time.captureFramerate로 프레임 간격을 고정해 매번 같은 결과가 나온다.
  • 결과 파일은 logs/*_results.xml로 단계별로 남겼다.

7. 진행 중 겪은 문제와 교훈

문제 교훈
발 미끄러짐 테스트가 처음엔 "통과"였지만 실제로는 다리가 전혀 움직이지 않았다 (Animator 컬링) 통과한 테스트도 측정값이 말이 되는지 확인한다. 기록을 남기는 습관이 문제를 드러냈다
편집 모드 캡처에서 흰 여우가 갈색으로 보임 조명 방향도 문제였지만 근본 원인은 편집 모드 렌더링. 실제 게임과 같은 조건(Play 모드)에서 확인한다
카메라가 가깝고 치우쳐 보인다는 피드백 원인이 Game 창 Scale 5배였다. 되돌릴 수 있게 커밋을 나누고, 되돌린 이유도 남겼다
배치 모드 테스트에서 R 키 입력이 안 들어감 Input System은 창 포커스가 있어야 키보드를 받는다. 테스트 동안만 설정을 바꾸고 되돌린다
Unity 에디터 시작 시 Search 에러 게임과 무관한 Unity 내부 에러. 색인 추가로는 안 없어졌고, 시작 시 색인 갱신을 꺼서 해결

8. 실행 · 다시 만들기

목적 방법
게임 실행 VoxelFox/Build/VoxelFox.exe (창 모드 1600×900, Alt+Enter 전체 화면)
에디터에서 바로 플레이 Unity 메뉴 VoxelFox > Play Main Scene
여우 다시 만들기 bash tools/build_fox.sh (Blender → FBX → Unity 설정 → 미리보기 → 테스트)
씬 다시 조립 + 전체 테스트 + 미리보기 bash tools/build_map.sh
실행 파일 빌드 bash tools/build_windows.sh
문서 HTML 갱신 python tools/make_todo_html.py (TODO·작업 기록·이 보고서)
